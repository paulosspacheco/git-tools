git-tools

Scripts Bash que transformam cada operação do Git em um comando curto. Eles perguntam o necessário, montam a mensagem no padrão Conventional Commits e calculam a versão a partir dos commits. Funcionam no terminal, em diálogos gráficos, no menu do gerenciador de arquivos e no menu Tools do Lazarus. Foco em Linux.

Leia de cima para baixo: é o caminho de um trabalho, da pasta solta até o GitHub. Ponto cheio: já funciona. Ponto vazio: planejado. No quadro tracejado ficam as ações que acontecem ao lado do passo principal.

    Como cada comando de commit trabalha (feat, fix, breaking, refactor, docs)

    Repositórioexige um repositório Git na pasta atual
    Tipolista no Zenity ou menu numerado no terminal
    Mensagemusa o argumento ou pergunta
    Confirmaçãomostra tipo: ação : mensagem
    Commitgit add . e git commit

    feat!: sobe o MAJOR, 1.4.2 vira 2.0.0
    feat: sobe o MINOR, 1.4.2 vira 1.5.0
    fix: sobe o PATCH, 1.4.2 vira 1.4.3
    Os outros tipos não mudam a versão.

    A regra do git-version. Vale o maior nível encontrado entre os commits desde a última tag vX.Y.Z.
    Uma pasta por projeto

    Os commits usam git add .. Não crie o repositório na pasta Documentos inteira.

    Confira antes de confirmar

    Tudo o que não está no .gitignore entra no commit. Olhe o git status antes.

    Texto simples mostra o que mudou

    Markdown, HTML e .txt funcionam melhor. Word, LibreOffice e PDF são guardados por inteiro, sem mostrar o que mudou dentro.

    O código vale mais que o documento

    Se algum .md divergir do que os scripts fazem, vale o código.

    Sem recuperação para o que nunca foi commitado

    Nem o git-reset nem o git-undo-reset trazem de volta arquivos que nunca entraram em um commit.
